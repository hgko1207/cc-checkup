# cc-checkup

**저장소가 Claude Code를 팀으로 쓸 준비가 얼마나 됐는지 점검하는 CLI.**
건강검진표처럼 항목별로 통과·주의·실패를 보여 주고, 고치는 방법과 준비도 점수를 알려 준다.

## 이런 결과를 낸다 (목표 화면)

```
팀 도입 준비도: 42 / 100

✓ CLAUDE.md 54줄
✗ CLAUDE.md에 검증 명령이 없습니다
    → 타입체크·린트·테스트 명령을 "검증 명령" 섹션에 적으세요
✗ .env 읽기가 막혀 있지 않습니다
    → .claude/settings.json의 deny에 Read(**/.env)를 추가하세요
! git restore가 자동 허용입니다 (커밋 안 된 작업이 묻지 않고 지워질 수 있음)
    → allow에서 빼고 ask로 옮기세요
✗ 위험 명령 차단 훅이 없습니다
✗ 작업 계획 파일(plan.md)이 없습니다
```

## 누가 언제 쓰나

| 누가            | 언제                              | 무엇을 얻나              |
| --------------- | --------------------------------- | ------------------------ |
| 팀 리드         | 도입 상담 전                      | 지금 상태와 고칠 곳 목록 |
| 개인 개발자     | 내 저장소 세팅을 점검하고 싶을 때 | 무료 자가 진단           |
| 세팅 대행(규니) | 상담·견적, 세팅 전후 비교         | "42점 → 90점" 같은 근거  |

## 사용법

```
npm install
npm run build
node dist/cli.js <저장소 경로>
```

종료 코드: 실패 항목이 있으면 1, 없으면 0.

## 지금 상태 (v0.1)

진단 항목은 **CLAUDE.md 존재·길이** 하나다. 나머지 항목, 점수, JSON·Markdown 리포트는 [docs/PRODUCT.md](docs/PRODUCT.md)의 로드맵대로 추가한다.

## 개발

| 용도     | 명령                |
| -------- | ------------------- |
| 타입체크 | `npm run typecheck` |
| 린트     | `npm run lint`      |
| 테스트   | `npm test`          |
| 포맷     | `npm run format`    |
| 빌드     | `npm run build`     |

진단 하나는 `src/checks/<이름>.ts`에 `Check` 함수로 만들고, `src/cli.ts`의 `CHECKS`에 등록하고, `test/<이름>.test.ts`에 테스트를 둔다. 예시는 `src/checks/claude-md.ts`.
