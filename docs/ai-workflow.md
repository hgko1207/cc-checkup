# 우리 팀 AI 코딩 가이드

> 대상: 이 저장소에서 Claude Code를 쓰는 팀원. 새로 온 사람도 이 문서 하나면 팀과 같은 방식으로 쓸 수 있습니다.

## 처음 한 번

1. Claude Code CLI를 설치하고 팀 계정으로 로그인합니다. ({{요금제·계정 담당자}})
2. 저장소를 열고 `claude`를 실행합니다. VS Code를 쓰면 권장 확장 설치 안내를 따릅니다.
3. 팀 플러그인 설치 안내가 뜨면 승인합니다. 안 뜨면:
   ```
   /plugin marketplace add {{org}}/team-ai-kit
   /plugin install team-ai@team-ai-kit
   ```
4. "검증해줘"를 한 번 입력해 검증 명령이 도는지 확인합니다.

## 기본 흐름: 계획 → 구현 → 검증

| 단계 | 하는 일 | 쓰는 것 |
|---|---|---|
| 계획 | 무엇을 어떻게 바꿀지 정해 `plan.md`에 적기 | "○○ 계획 세워줘" (plan-feature) |
| 검토 | 계획을 직접 읽고 엣지 케이스·컨벤션 보태기 | 사람 |
| 구현 | `plan.md` 다음 작업을 위에서부터 | "plan.md 다음 작업 구현해줘" |
| 검증 | 타입체크·린트·테스트를 실제로 실행 | "검증해줘" (verify) |
| 리뷰 | PR 전 자가 리뷰 | `/team-ai:review-pr` |
| 커밋 | 팀 규칙대로 나눠서 커밋 | `/team-ai:commit` |

작은 수정(오타, 한 파일 몇 줄)은 계획을 건너뛰어도 됩니다.

## 요청을 잘 쓰는 법

요청은 "알아서 해줘"가 아니라 **스펙**으로 씁니다.

```
[맥락] 왜 하는가
[제약] 지켜야 할 것, 건드리면 안 되는 것
[참조] 따라 할 기존 코드 경로
[검증] 무엇이 통과하면 끝인가 (예: 기존 테스트 통과 + 취소 테스트 2개 추가)
[형식] 결과를 어떤 형태로 받을지
```

- 반복되는 규칙은 요청에 매번 쓰지 말고 CLAUDE.md에 넣자고 팀에 제안합니다.
- 작업이 끝나면 `/clear`로 대화를 끊고, 다음 작업은 새로 시작합니다.
- 방향이 틀어지면 ESC 두 번으로 되돌린 뒤 다시 요청합니다. 실패한 시도가 대화에 남지 않게 합니다.

## 자동으로 동작하는 안전장치

- `.env`, 키 파일은 수정이 차단됩니다.
- 강제 푸시, DB 삭제, 인프라 변경 같은 명령은 차단됩니다. 꼭 필요하면 직접 실행합니다.
- 파일 수정 후 팀 포맷터가 실행됩니다.
- 대화가 길어져 압축되면 plan.md의 남은 작업이 다시 들어갑니다. (CLAUDE.md는 Claude Code가 자동으로 다시 읽습니다.)
- 규칙은 `.claude/team-ai.json`, `.claude/settings.json`에 있습니다. 바꾸려면 PR로 제안합니다.

## 선택 기능

필요해지면 팀과 상의해 켭니다.

```
/plugin install team-ai-extras@team-ai-kit
```

- `fix-issue`: 근본 원인부터 찾는 버그 수정 절차
- `refactor`: 안전망 확보 후 작은 단계로 하는 리팩터링
- `verifier` 에이전트: "이 지적이 진짜인지 확인해줘" 같은 반증 검증

## 개인 설정

팀 설정을 덮지 않고 개인 설정을 더하려면 `.claude/settings.local.json`과 `CLAUDE.local.md`를 씁니다. 둘 다 커밋하지 않습니다.
